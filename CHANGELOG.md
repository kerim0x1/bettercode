# Changelog

All notable changes to BetterC0de are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

A `v<version>` tag can only be released when this file has a `## [<version>]` section. The release workflow publishes that section as the GitHub release notes, and the pre-push hook refuses the tag without it.

## [Unreleased]

### Security

- **Opening a repository no longer runs its code.** On Windows, git, shells and helper tools are resolved to absolute paths and never searched in the workspace folder, so a `git.exe`, `powershell.exe` or `codex.bat` committed to a repository is not executed; the backend also sets `NoDefaultCurrentDirectoryInExePath`. CLI sync no longer copies a repository's MCP servers, skills or agents into your global lists, and project MCP servers (local or remote), formatters and Claude project hooks run only in a workspace you trusted explicitly. Project servers can't replace one of your own.
- **Workspace trust is opt-in for new installs.** Opening a folder no longer trusts it automatically. An Agent turn refused in an untrusted folder offers **Trust this workspace**, which asks for confirmation and resends the message; **Trust project** in Settings → Permissions does the same. Existing installs keep a saved choice, and folderless chats still work. Review your MCP list once: servers imported from projects before this release carry no origin and still run in every workspace.
- **MCP secrets stay out of view.** Environment values and headers in `mcp-servers.json` are encrypted on disk and shown as `••••••••`; leaving the placeholder keeps the stored value. The system prompt names MCP servers only, never their commands, URLs or credentials.
- **Paired devices have tighter limits.** Plain-HTTP LAN pairing gives a one-hour read-only session, also for the WebSocket; full sessions need HTTPS, Tailscale or this computer. A device without the terminal grant can't run Bypass turns or save permanent permission rules. Idle sessions end after 7 days, pairing links last at most one hour, and turning remote access off revokes sessions and unused links. Settings → Remote Access lists unused links with **Revoke** and **Revoke all** and labels read-only devices. On the phone, Bypass shows as unavailable until the desktop allows terminal access from remote devices, and approvals offer **Allow for this session** instead of lasting rules the desktop doesn't save from a phone.
- **Saved commands need a native confirmation.** Adding or changing a hook command, saving or importing an MCP server with a new or changed command, and installing a Claude Code or Codex plugin show a native dialog with the exact command; approved hooks then run automatically. Existing hooks run only right after a click or key press until they are saved again; Settings → Hooks shows which commands are approved, and cancelling the approval keeps the form open with “Not saved: the command wasn't approved.” An unreadable `hooks.json` now stops the send with an error instead of silently skipping blocking hooks. Blocking message hooks now run in the backend for every client, including the remote web UI and every `/goal` command that starts work, and no longer run twice when a provider plugin fails and the message falls back to a built-in provider, and a message is refused while `hooks.json` is unreadable or a hook's command isn't approved.
- **Electron hardening.** Packaged builds set Electron fuses (`NODE_OPTIONS`, `NODE_EXTRA_CA_CERTS` and `--inspect` are ignored, cookies are encrypted, only `app.asar` loads, with integrity checks), drop the macOS DYLD entitlement, keep DevTools closed unless started with `BETTERC0DE_ENABLE_DEVTOOLS=1`, and no longer allow `unsafe-eval` or inline scripts in the renderer; the page served to remote browsers uses a per-response nonce. Preview pages can't open popups, navigate to `file:` or browser-internal pages, forward typed keys, or add selected elements to a chat without a user action.
- **Privacy by default.** Automatic crash reports and the usage ping are off unless turned on in Settings → Privacy & Diagnostics. When enabled, uploads and logs are redacted, the ping is sent once per start, and the installation ID is deleted while the ping is off.
- `full` and `full-access` permission levels now mean allow-edits for every provider; only an explicit Bypass grants bypass, and a session without a stored mode no longer falls back to bypass. Image generation asks for approval except at Bypass and runs without network or shared temporary-folder access.
- The unused **Sign in with ChatGPT** option was removed, and leftover ChatGPT tokens (`auth.json`) are deleted at startup.

### Fixed

- **Agents and providers.**
  - On the Claude API and OpenAI-compatible providers, a Write or Edit cut off by the output limit is never run, so it can no longer empty a file. Tool turns get a larger output allowance.
  - Active agent turns are no longer cut off after 30 minutes (10 minutes for direct API turns); only a stretch without any activity ends a turn, and waiting for your approval or answer doesn't count. Approvals and questions no longer resolve or deny on their own after 5 minutes for Claude Code, API, Cursor or Grok agents. `BETTERC0DE_PROVIDER_TURN_TIMEOUT_MS`, `BETTERC0DE_PROVIDER_TURN_MAX_DURATION_MS` and `BETTERC0DE_PROVIDER_MAX_IDLE_SESSIONS` tune the limits.
  - A single 429 or 529 from an API key is retried with backoff before the turn fails. A rate-limited key is set aside for at most 5 minutes, and **Retry now** in the key settings clears the wait.
  - Claude Code installed through npm on Windows works again: turns no longer fail with `EINVAL` while the provider status looks healthy.
  - Image attachments reach Claude Code and Grok or Cursor agents that accept images; other attachments show a notice instead of being dropped silently.
  - **Stop** works reliably on Grok and Cursor and right after sending on Codex, and one very large protocol message no longer ends a Codex, Grok or Cursor session.
  - Agent CLIs keep your non-secret environment (SSH agent, locale, proxy and Windows system variables) while credentials of other tools are removed. On Windows the agent's Bash tool uses Git Bash when it is installed and rejects multi-line commands under `cmd.exe` instead of running only the first line. Stop and timeouts end the whole process tree.
  - On macOS, apps launched from Finder or the Dock find tools installed with Homebrew, nvm or volta.
  - Claude Terminal finds its transcript on Windows and for project paths with special characters, and trims history so the command line stays within OS limits.
  - Idle agent processes are released after 10 minutes, with at most 4 kept warm per provider instance. The provider status warns about an outdated Codex CLI.
- **App lifecycle.**
  - The backend restarts itself after a crash; after repeated crashes a banner offers **Restart backend**. A crashed window reloads, and a hung window offers **Wait** or **Reload** instead of a blocking error box.
  - Closing the window while the app starts no longer shows a failure dialog, and launching again while the app shuts down relaunches it.
  - Terminals and dev servers a window started end when that window crashes, reloads or closes, and windows reconnect to the backend right after the computer wakes from sleep.
  - The first window appears sooner: plugin loading, the settings key and CLI scans no longer block it, and the CLI scanner no longer reads files synchronously on the main thread.
  - Plugins load after the window appears. A plugin that throws from a timer or listener is disabled instead of quitting the app, and plugin calls time out after 120 seconds.
  - In development (`npm run dev`), a rebuilt shared schema package restarts the backend too, so a new setting is no longer rejected as invalid until the whole app is restarted.
- **Chats, memory and performance.**
  - Opening a chat no longer downloads every diff and inline attachment; diffs load when expanded and attachments when shown. Very large tool output keeps its first and last part with the original size, and **Show full output** loads the rest while the backend still keeps it.
  - Long chats offer **Show earlier messages** and load older history while you scroll up, so messages before the last turns can be read again and chats over 1,000 messages show their full history. Opening a chat reads the newest 100 messages.
  - A message sent during a reconnect refresh no longer disappears.
  - **Autonomous Work runs in the backend.** A run keeps going after a window reload or with no window open, comes back paused after a backend restart, and its controls and state are shared across windows and paired devices with full access. Resume sends the next turn as soon as the chat is idle. A run needs conversation auto-save and a provider BetterC0de runs itself, and it can't start while a goal is active in the same chat (or the other way round). Follow-up turns use the model chosen at start or resume.
  - A chat's permission level, model selection and orchestration are stored with the chat in the backend, so they survive restarts, appear on other devices and update other open windows right away. The remote web UI's turns now include your skills, MCP servers, subagents and rules, prepared by the backend exactly like desktop turns.
  - Phone plan approvals show the plan text, also when it arrives after the card opened.
  - Desktop and phone derive open approvals and questions from one shared rule. A question or plan approval closed by a resolution of another kind (for example a question the provider cancelled) no longer stays open on the desktop, a question request without questions offers a free-text answer on both, and the phone lists requests in the desktop's order.
  - Memory stays bounded: the least recently used chats free their messages and activity, checkpoints, closed editor tabs, terminal output and canvas logs are capped, closed tabs release their Monaco models, off-screen canvas previews pause, and the right-panel browser releases its page after 5 minutes hidden.
  - Streaming no longer re-renders the composer, sidebars, title bar or right panel, and providers are polled once per window instead of once per pane.
  - `/undo` no longer downloads every diff of the thread, and Git status no longer blocks the backend with synchronous `git config` calls.
  - Rules, skills, MCP servers and hooks are kept in one place owned by the backend, with locked, atomic saves; older values from `settings.json` are moved there automatically without losing anything. A custom data folder no longer loses hooks, skills or rules, the prompt names exactly the MCP servers a turn attaches, and Settings → Hooks shows the last run of message hooks again. A paired browser on a full session shows your global rules read-only in Settings → Rules; read-only sessions are told why they're hidden.
  - Settings → Skills → **Sync from CLI** no longer erases your MCP servers or imported Claude plugins, and no longer counts project skills it doesn't import; onboarding import adds to the existing list.
  - **Reject** in the review bar now restores a file to its state before the turn, using the turn's Git checkpoint; it appears once the turn has finished. Before, it wrote the edited content back and reported success. Outside Git repositories Reject is no longer offered.
  - Typing a `/` command or `@` mention, console output and opening dialogs no longer re-render the whole window.
  - The copy, retry and revert actions under an answer are always visible instead of appearing only on hover, and they and the turn duration use the full muted text contrast.
- Claude Code turns in Agent mode, and the implementation after you approve a plan, no longer stop after 50 steps with "Reached maximum number of turns (50)" and no final answer. Like the Claude Code CLI, they run until the work is done, you press Stop, or nothing happens for 30 minutes. Asking and planning keep their limits, and agent loops BetterC0de runs itself with an API key stop after 200 steps instead of 50. A failed turn's error now shows once instead of twice.
- Codex context usage reaches the app. The app-server reports usage as `total`, `last` and `modelContextWindow`, which BetterC0de read as empty, so Codex chats showed no context fill and BetterC0de could compact them on top of Codex's own automatic compaction.
- Claude is greyed out with a lock in the model menu when Claude Code is not installed or not signed in. Without a `claude` of its own the desktop app falls back to the Agent SDK's bundled binary, which starts but has no login, and BetterC0de took that as a ready provider. The hover hint now says to install Claude Code or run `claude auth login`.
- Grok CLI models now work as orchestration workers. The worker catalog missed the runtime's `grok-cli` driver spelling, so every orchestrated turn with Grok selected failed with “No available Grok worker models” even though Grok worked as the main model.
- Orchestration workers no longer offer or run Ultracode. It starts Claude Code's own multi-agent run, which conflicts with a worker's assignment; a saved Ultracode selection now falls back to Auto. The main chat keeps Ultracode.
- **Orchestration controls.** A dedicated icon beside permissions brightens when orchestration is on and opens a 300px menu in the model picker's dark chrome with the chat thinking slider. The menu has a switch-style toggle and a live summary of the lead and its delegates, and lays the team out as a tree: connector lines run from the main agent to each provider and on to its models, lighting up for selected ones. Providers expand in place with checkbox rows and per-model thinking chips instead of nested flyouts, with selected/available counts; the footer note shows the selection or any state that needs attention. Provider rows preview selected models; each model's thinking submenu preserves supported effort IDs and can reset to Auto. Centred above the composer footer, an Orchestration heading with the model count sits over a row of the selected models, each showing its provider logo beside its colored thinking-level icon; from the sixth model the rest collapse into a **+N** count. Hover or keyboard focus reveals each model's name and colored thinking level, including account-specific names and saved selections, and a click opens that model's thinking slider directly from the row. Selection counts, pending changes, and unavailable states remain visible, with keyboard navigation and focus restored when dismissed.
- Claude Code keeps the Ultracode prompt mode when SDK model discovery refreshes its native effort levels, including Opus 5.5. The mode remains separate from the SDK effort value.
- **Reasoning selection stability.** The slider keeps its selected value while preferences catch up, retains keyboard focus, and discards stale previews when switching models or threads. Offered effort levels survive preference reconciliation and use the provider's actual option ID and value in requests, including Cursor reasoning, Grok efforts, and Claude Extra High. Models with a boolean Thinking capability expose On/Off; Claude Haiku now honours that toggle in SDK settings.
- Cursor shows its cube logo in the model menu, the model chip and everywhere else a provider logo appears, instead of a generic terminal icon.
- Models in Cursor's and OpenRouter's model menus show their maker's logo (Claude, OpenAI, Grok, Gemini and others) instead of repeating the provider's; Auto and Composer keep the Cursor cube.
- The composer's **Model** menu row shows the active provider's logo, matching the selected model chip and respecting the current theme. **Reasoning** uses a larger ascending level icon, which the compact composer's model chip also shows before the level name (and keeps when a narrow column hides the name), and a compact picker with the selected level and model centred above a rounded slider with snap points and a prominent thumb. High uses orange, Extra High red, Max blue, and Ultra/UltraThink/Ultracode purple across the level name, icon, and slider fill, with light/dark contrast variants. Reset stays in the header; click, drag, and keyboard selection remain available. While Fast mode is on, the model chip leads with a filled purple bolt.
- **Large project file trees.** The Explorer loads the workspace root and opened folders directly instead of stopping at a recursive search limit. Very large folders offer **Load more files**, expanded folders keep their contents when refreshed, and revealing a file loads its ancestors and any required continuation pages. The header count identifies loaded entries rather than claiming a project-wide total.
- OpenRouter models read like the others: "Gemini 4 Argon" instead of "google/gemini-4-argon" in the model picker, the composer chip, the message header and the model-switch line, with the maker's logo (the exact id stays under the name in the picker). Their thinking shows in the chat: BetterC0de now asks OpenRouter for reasoning through its own `reasoning` setting, at the level chosen in the composer.
- MCP servers saved without arguments or environment variables (an HTTP server, or a command with no options) are no longer left out of turns the backend prepares or of agents it starts directly, and the prompt lists them again.
- Switching a chat to another provider no longer fails when the previous one can't run (for example a Grok CLI that quits on start because one of its MCP servers needs a sign-in). Instead of blocking with "The previous provider could not prepare the handoff summary", the most recent part of the stored conversation is passed on as recorded, and the handoff says so.
- Sending to OpenRouter and the other API-key providers no longer crashes the local backend ("Error: chat send failed" and an automatic restart). The model picker sends an instance with the model, which the durable send record kept while the accepted turn was bound without one; the two now agree.
- In Editor mode, Settings and Usage sit in the same rounded card as in Agent and Canvas mode instead of running edge to edge against the sidebar.
- The Usage activity calendar steps by calendar days. It added fixed 24-hour steps from midnight, so across a daylight-saving change two cells landed on the same date (React warned about the duplicate key `2025-10-26`) and a day went missing.
- The Usage tab loads in well under a second once its cache exists. Claude transcripts that grew since the last visit are read on from where the last scan stopped instead of from the start, which for an active chat's 100 MB transcript took several seconds on every visit; a transcript that was rewritten is still read in full.
- Windows provider cleanup allows busy process-tree termination to finish and retries a partial Codex tree traversal once while its root is still alive, avoiding unnecessary cleanup quarantine under load.
- **Cursor CLI detection and models.** Native Windows installs are found without adding the CLI to `PATH`. Cursor's available models and options come from its signed-in ACP session, with account-specific cached results; provider refresh rechecks them. Model selection uses the exact ACP value, and stable CLI channels are no longer rejected by a fixed gate.
- **Slow Cursor ACP starts no longer immediately disable the provider.** Cursor and Grok ACP session starts and stops use longer bounded deadlines, and stopping a provider cancels a session that is still starting before it can leave a late process behind.
- **Every setting does what it says.** Each settings row has an icon and a description of what it changes; settings without an effect are gone.
  - **Chat → Text:** Message Text Size now sizes the messages themselves; before, it only changed the space around them, so its 14px default never showed. The default stays at the 13px messages had, and a size you picked carries over. Compact Messages, moved here from Layout, now tightens the space between messages. Reasoning Summaries is disabled while Thinking Blocks is off.
  - **Layout:** Workspace Sidebar, Terminal, Chat UI Style, Chat Width and Chat Scale are removed; none of them changed anything. Sidebar Width now sets the real sidebar width, the same one dragging its edge changes. Files View and Review / Diff follow the mode: the right panel in Agent, the left sidebar in Editor and Canvas. In Agent mode, Review / Diff opens the right panel's Diff view and shows whether it is open; before, it switched an inline panel that never appeared.
  - **Appearance:** Theme Mode Lock (no effect) and Save (changes save on their own) are removed, and Export, Import and Reset sit in a Backup group. An imported theme keeps its own accent color instead of losing it whenever another appearance setting changed, Hue also tints at red, and Reduce Transparency's solid borders now apply in dark themes. Import checks the JSON, applies the theme it contains and says when the text isn't an export; Reset also restores the default theme and mode. Terminal Titles sits next to the terminal font, and the default UI font is named Figtree.
  - **Notifications & Sound:** system notifications work in the desktop app; the app refused their permission, so they never appeared. The permission row explains its state, and a new In the app group has Error Toasts and Attention Badges, which were saved settings without a switch.
  - **General:** Confirm Archive and Confirm Delete are honoured. Archiving a chat from a menu asks first (it never did), deleting a chat skips the question when Confirm Delete is off, and deleting all chats of a project always asks.
  - **Permissions:** Claude Code's rule files show the Claude logo and say when rules are saved, lists show "Loading rules…" instead of "No rules" while they load, and the copy is plainer. **Remote Access:** the Reachability text is one sentence and the "Test the recommended link" link is gone.
  - **Rules:** if your rules file can't be read, the editor stays read-only with a Retry button so saving can't overwrite it; save errors are shown; "Use starter rules" asks before replacing your rules. The prompt preview is labelled as approximate, and rule files show which tool reads them (Claude Code, Codex, Cursor). Rules and Compatibility use the chat's worktree when it has one, matching what the agent sees.
  - **Docs:** "API Reference" (a dead link) is now "Product guide"; Getting Started points to Settings → Providers and corrects its slash command and Diff panel steps.
  - **Hooks:** event descriptions say exactly when each hook runs, deleting a hook asks first, paired browsers say hooks are managed on the desktop, and an unreadable hooks file shows an error instead of an empty list.
  - **Compatibility:** one failed request no longer blanks the page; developer reference tables are removed, and instruction, skill and provider rows show tool logos.
  - **Experimental:** clearer Orchestration and Jev code search descriptions with the providers they apply to, and plainer save errors.
  - **Skills, MCP and Plugins:** MCP servers, skills and subagents imported from Claude Code or Codex stay removed or hidden; only "Sync from CLI" brings them back. HTTP and SSE MCP servers can be edited without losing their URL or headers, imported servers show where they came from, and "Sync from CLI" lists what it imported and skipped. "Sync from CLI" also imports Claude Code agents and reports failures instead of saving empty copies; skills managed by Claude Code or Codex can be opened or hidden. Plugin config fields no longer drop characters while typing, and install, toggle and remove failures show the reason. All three confirm deletions, warn before replacing an item with the same name, and say in a paired browser that they're managed in the desktop app.

### Added

- **Pull requests in the app.** The Git panel and the chat header can create a pull request for the current branch, or commit, push and create one in a single step: the title and description are written from the branch's commits and diff, and you can edit them, pick the base branch (the repository's default first) and make it a draft. The branch is published or pushed first when needed. If you are on the default branch, the dialog suggests a new branch name to create; if the branch already has a pull request, it shows that one. The new pull request appears on the chat and in the sidebar right away. A new **Pull Requests** page (sidebar, or **Pull Requests** in the command palette) lists the open pull requests of your projects with Mine, Review requested and All open filters, search, checks and review state. Opening one shows its description, checks, changed files and conversation, and lets you comment, approve or request changes, merge with a method the repository allows (optionally deleting the branch), close or reopen it, open it on GitHub, **Work on this PR** in a new chat on a worktree of its branch, or **Ask the agent to review** it in a read-only chat. A pull request from a fork opens in an untrusted folder, so its hooks and tools run only after you have read it and trusted the folder. Everything goes through your GitHub CLI login (`gh`); without it, or signed out, the app says what to install or run.
- **Wake a chat on CI failures and reviews.** Turn on **Wake on CI failure or review** from a chat's pull request in its header. When a check fails on the latest commit, a collaborator on the repository (or a review bot) reviews or comments, or the branch stops merging cleanly, the chat gets a message with the details (for a failed GitHub Actions job, the end of its log) and starts working; if it is busy, the message waits in its queue. Your own comments never wake it, a chat is woken at most once every ten minutes and twelve times a day, and watching stops when the pull request is merged or closed. Wake-ups are turned on from the desktop app.
- **Automations.** **Scheduled** in the Agent sidebar (or Ctrl+Shift+A) now opens an Automations page instead of the hooks settings. An automation runs a prompt in a trusted project with the provider, model, reasoning level and permission preset you choose, in the project folder or in a new Git worktree for each run: once, every few minutes or hours (at least every 5 minutes), daily at a time on the weekdays you pick, on a cron expression, or whenever its webhook URL is called. Each run starts its own chat named after the automation and the date, which says it came from the automation; the page shows the next run, the last 50 runs with a link to each chat, and lets you run now, pause, resume, edit and delete. A run missed while the app was closed runs once at the next start, and a run that comes while the previous one is still going is skipped and listed. Webhook URLs carry a random token (**Rotate URL** replaces it), accept JSON, form or text bodies up to 256 KB, can check GitHub's `X-Hub-Signature-256`, are rate limited, keep a log of the last 50 deliveries, and put request values such as `{{body.pull_request.title}}` into the prompt as clearly marked untrusted data. The page lists the URL for each address Remote Access offers, or says that only this computer can reach it while Remote Access is off. See [Automations](docs/automations.md).
- **Bring your Claude Code and Codex conversations.** Setup has a new step after the CLI check, and Settings → General → Chats & History has **Import from Claude Code and Codex**: both list the conversations those CLIs keep on this computer (the newest 200 of each), grouped by project, so you can pick whole projects or single chats and import them with a progress bar. Each becomes a chat in the project of the folder it ran in, or a chat without a folder when that folder is gone, with its prompts, replies, the reasoning the CLI showed and its tool calls in short form; system prompts and hidden reasoning stay out. A note at the top says where it came from. Continuing an imported chat resumes the original Claude Code or Codex session when it uses the same CLI home and folder; otherwise the earlier messages go along as context. A conversation can be imported only once, and sessions that BetterC0de's own chats ran aren't offered. Import is available in the desktop app only.
- **A real terminal on the desktop.** The terminal panel now runs your shell interactively instead of one command at a time, so `npm run dev`, vim, ssh, Ctrl+C and anything else a terminal does work. Each chat has its own terminals, started in its folder or worktree, in the bottom panel or a pane's Terminal tab: `+` opens another tab and its chevron picks the shell (cmd, PowerShell, Git Bash, WSL, bash or zsh), a double-click renames a tab, and Ctrl+D or Ctrl+Shift+D splits the focused terminal right or down, up to four per tab, with dividers you can drag. Terminals keep running while the panel is hidden or you switch chats, tabs or panes; closing one ends it, and asks first while something still runs. After a window reload they show as ended, with **Restart**. Selecting text copies it, Ctrl+Shift+C and Ctrl+Shift+V copy and paste (Ctrl+V too on Windows), right-click pastes (or copies a selection), Ctrl+click (Cmd+click on macOS) opens web addresses, and the colors follow your theme, including an imported theme's terminal colors. Shift+Tab and Alt with the arrow keys go to the shell while it has focus, and Ctrl+D splits instead of ending the shell, so type `exit` for that. On macOS the splits are Cmd+D and Cmd+Shift+D, and Ctrl chords such as Ctrl+D, Ctrl+R and Ctrl+W stay with the shell. Ctrl+` and Ctrl+J still show and hide the panel, and programs that ask the terminal for its cursor position or colours get their answer even while you aren't typing. The desktop can now run 12 terminals at once instead of 4, and typing no longer counts against the limit for running commands.
- **Visual replies.** Agents can answer with a live page, such as a chart, table, diagram or UI mockup, and the chat shows it right in the conversation once the agent has finished writing it. The page follows your light, dark or imported theme and grows with its content up to a scrollable height; its toolbar switches between the page and its code and offers **Copy HTML**, **Save as file** and **Full screen** (Escape closes it). Ordinary HTML code blocks get a **Preview** toggle next to Copy. Pages run in a sandbox without access to the app or your data and can load scripts, styles and fonts only from a few public CDNs. Turn it off in Settings → Chat → **Visual Replies**; agents then aren't told about it and such pages show as code.
- **Find in chat.** Press Ctrl+F (Cmd+F on macOS) in a chat, or choose **Find in Chat** in the command palette, to search the open chat. A small bar at the top right of the conversation shows "3 of 12", with previous and next, **Match case** and close; Enter and Shift+Enter (or F3 and Shift+F3) move between matches and Escape closes it. Matches are highlighted in your messages, the replies and recorded plans, with the current one in a stronger colour, and the chat scrolls to it. It searches the whole chat, including older messages that aren't loaded yet: going to one of those loads that part of the history. Results update as new messages arrive, and past 1,000 matches the count reads "1000+". Ctrl+F in the code editor and the browser preview still opens their own find, in a terminal it stays with the shell, and Ctrl+Shift+F still searches across chats.
- **Compare models.** In a new chat, Shift-click or Ctrl-click (⌘-click on macOS) models in the model menu to send one prompt to up to four models at once, each with its own reasoning level. The model chip shows "3 models" with their logos, and a click without a modifier goes back to one model. Sending opens one chat per model with the same prompt, attachments and permission level, titled after the model ("Fix login · GPT-5"). In a Git repository each chat gets its own new worktree; in a folder without Git you're asked first, because the chats would edit the same files. The first chat stays open while the others run in the background, and a **Compare** switcher in the chat header (with a marker in the sidebar) jumps between them and shows how each one is doing.
- **Edit a message, fork from an answer, merge a fork back.** Hover one of your messages and choose **Edit and resend** (also in its `…` menu) to change it in place: Enter sends, Escape cancels, and its attachments go along unless you remove them. The chat goes back to just before that message, the agent forgets the later turns, and the edited text goes out as a new turn. When the agent changed files after that point you choose **Keep file changes** or **Revert files too**, which restores the folder from its checkpoint and says why it is unavailable outside Git or without a checkpoint; a running turn is stopped first, after you confirm. **Fork from here** under an answer starts a new chat with the history up to that answer, folded under its parent like `/fork`, which now also takes a message number as `/messages` lists them. A forked chat shows which chat it came from, and **Merge back** (or `/merge-back`) sends the parent the fork's last answer and the files it changed as a new message, queued if the parent is busy, and opens the parent. Forks work in the same folder or worktree as their parent.
- **Steer a running turn, and edit the queue.** While the agent works, a message can go into the running turn right away so the agent changes course, instead of waiting for the turn to end. Settings → Chat → **While the agent works, Enter…** chooses whether Enter queues the message (the default) or steers, and Ctrl+Enter (⌘Enter on macOS) does the other one; the send button and its tooltip show which. Codex takes the message in the middle of its turn. Other agents can't, so for them steering stops the current step and sends the message as the next turn, and the tooltip says so. A steered message shows in the chat as yours, at the moment you sent it. Queued messages get **Steer now** and a menu to edit them in place (text, attachments and tagged elements; Enter saves, Escape cancels), move them up or down, or remove them. Drag a queued message to reorder the queue, and press Alt+↑ in an empty composer to edit the last one. The queue is still saved on this computer and pauses after a restart, and a message you are editing waits until you're done.

## [0.1.0-beta.3] - 2026-09-25

### Distribution and known issues

- Desktop installers remain unsigned. Windows and macOS users install updates manually; see [code signing](docs/development/code-signing.md) for first-launch steps.
- BetterC0de Remote is built and tested in CI, but its APK and TestFlight build are not published until mobile release credentials and distribution are enabled.
- `npm audit --omit=dev` reports 14 moderate findings in the Expo and Expo Router dependency tree, with no high or critical findings. The locked mobile dependencies remain in this beta; address the findings with a separate mobile dependency update.

### Fixed

- **macOS CLI discovery.** Finder-launched builds can resolve installed Claude, Codex, and Grok command-line tools when the app receives a minimal `PATH`, including normal turns and provider handoffs.
- **macOS Apple Silicon downloads contain an Apple Silicon build.** In 0.1.0-beta.2, `BetterC0de-0.1.0-beta.2-arm64-mac.zip` and `BetterC0de-0.1.0-beta.2-arm64.dmg` contain the Intel (x86_64) app. The target configuration overrode the build's architecture flag, so each Mac build job packaged its one app under both architectures' names, and the Intel job's files are the ones that were published.
- **macOS update metadata lists both architectures.** `latest-mac.yml` was taken from whichever Mac job uploaded last; it is now merged from both, and every entry is checked against the published file's sha512 before release.
- **Start-up failures explain themselves.** When the background service cannot start, the dialog shows the lines the service printed and what to do (reinstall the matching build, rebuild native modules, free disk space, fix folder permissions), instead of only "Failed to start backend: Node backend exited (code=1 signal=none)".
- **Building from a symlinked directory.** `npm run build:backend` refused a checkout reached through a symlink, such as one under macOS `/tmp` or a linked home directory. Symlinks inside the workspace are still refused.
- **Phone app dependencies.** Two versions of `react-native-gesture-handler` (2.31 and 3.1) were installed side by side, so the app linked one native version and could bundle the JavaScript of the other. The monorepo now resolves a single 2.31.x.
- **Remote access documentation.** It described a separate switch for file access, which does not exist: a full session can read and change files, and only the terminal needs **Allow terminal from remote devices**. `.env.example` listed the BetterC0de provider's server login under remote access.
- **Windows installer checksum.** The installer is named `BetterC0de-Setup-<version>.exe` locally, in the release and in the checksum file. The checksum file used to list a name with spaces that did not exist in the release.
- **Phone app: all chats.** The chat list stopped at the newest 100 chats; it now loads older ones on request. Long chats load 200 messages at a time, with earlier messages on request.
- **Phone app: screens no longer jump back every minute.** The periodic session check replaced the pairing whenever the desktop updated the device's last-seen time, which sent the file browser back to the project root and reloaded the open chat.
- **Phone app: Stop stops the agent that is running.** It used to target the model chosen in the picker, or OpenAI, instead of the provider running the turn.
- **Phone app: Remote Access turned off on the desktop.** The app deleted its pairing and called it expired. It now says that Remote Access is off, keeps the pairing, and asks to pair again only when the desktop reports that it signed the phone out.
- **Phone app: read-only sessions.** A session that may only watch offered to send and approve, then failed with HTTP 403. It now shows chats and pending approvals without the controls, and says why.
- **Phone app: errors are shown.** A chat that failed to load read "Ready for first prompt", Projects showed an empty list, and the file viewer spun forever; each now shows the error and a retry. Binary files are no longer shown as text.
- **Phone app: signing out.** When the desktop could not be reached, signing out forgot the pairing on the phone and left the session active on the desktop. The app now keeps the pairing and offers to forget it on the phone only.
- **Phone app: a message sent again arrived twice.** After a send timed out, sending the text again made a second message with a new id. Retry now resends the same message, which the desktop recognises. The app also waits as long as the desktop does (up to 210 s) for a message whose chat is first compacted, instead of giving up after 20 s.
- **A chat's worktree mode is recorded where the worktree is made.** Creating, resetting or removing a chat's worktree left its env mode as the client that asked had last written it; a chat given a worktree by another client could read as local. The desktop's backend now sets it together with the worktree's path and branch.
- **Phone app: messages went out without the desktop's preparation.** The desktop runs its **on message send** hooks before each of its messages and gives the turn a system instruction (the mode and permission preset, the project, your skills, MCP servers and subagents, and the project's permission rules); messages from the phone got neither, only your rules and the project's rule files. The desktop now prepares them the same way: a hook that fails stops the message, and the phone says which hook and what it printed.
- **A commit of nothing says so.** With nothing staged, `POST /api/v1/git/commit` answered HTTP 500 "git commit failed": git exits with an error then, which ended the request before the desktop's own check. It now answers 400 `git_nothing_to_commit`, "Nothing to commit — stage changes first or modify a tracked file.", which the desktop's git panel shows too.
- **Phone app: long diffs.** A chat's changes showed at most 500 lines of a diff. Each turn's and checkpoint's diff now lists its files, and a file opens in full.
- **Windows: ending a terminal no longer puts the backend into an emergency drain.** When two teardowns of the same terminal overlapped (the app quitting while a paired device's terminals ended, for example), the second found the processes already gone, and the backend counted that as a process tree it could not end: it refused new work until it restarted. A shutdown also waited only half a second for Windows to report a force-ended terminal's exit, which it can take more than a second to do, and then kept the database open.
- **Phone app on Android: the keyboard no longer covers the message box.** The app draws edge to edge on Android, where the window no longer shrinks for the keyboard, and only iOS moved the message box and the pairing form above it: on Android the keyboard covered Send and Connect. The menu sheets now make room for the keyboard too, on both platforms: it covered the model search.
- **Phone app: smaller fixes.** File search keeps the desktop's ranking. A reply ends when its own turn ends, not by comparing the phone's clock with the desktop's. After a reconnect the app checks the session at once instead of keeping the composer disabled for up to a minute.

A row of keys adds what a phone keyboard lacks (Esc, Tab, Ctrl and Alt, arrows, Home/End, Page Up/Down), and VoiceOver and TalkBack read the output. The terminal keeps running on the desktop when the phone loses its connection, and the phone picks up where it left off, without output lost unnoticed or input run twice; after 15 minutes without the phone it ends. It uses the desktop's WebSocket (`terminal.ws`, see "Terminals for paired devices" in `docs/remote-access.md`). The desktop's own terminals are never shown on a phone.
- **Paired devices** on the desktop shows how many terminals each device runs, and **Close terminals** ends them while the device stays paired. The desktop's log records which device opened a terminal where, and when and why it ended, never what was typed or shown.
- `/api/v1/workspace/read` returns the file's SHA-256, size and whether it is valid UTF-8; `/api/v1/workspace/write` accepts `expectedSha256` and refuses to overwrite a file that changed since it was read.
- CI runs `release:check` on Linux x64, Windows x64, macOS arm64 and macOS x64 for every push and pull request, and the source checks on Node 24.
- The Linux `.deb` is installed with apt and started with the Chromium sandbox on in CI; the `.rpm` is installed in a clean Fedora container.
- A pre-push hook runs `release:check` before a release tag is pushed.
- Documentation of the unsigned-release policy and what users see (`docs/development/code-signing.md`), and this changelog.

### Changed

- Releases are published only after every platform passed, from one verified set of files. A failed platform no longer leaves a partial release behind.
- Releases carry a single `SHA256SUMS.txt` instead of one checksum file per platform.
- Releases are unsigned by decision; the Release workflow no longer passes signing secrets.
- Node.js 22.23.2 is the pinned build toolchain (`.nvmrc`). Supported for development: Node 22.15+ and Node 24.
- The phone app (BetterC0de Remote) carries the desktop's version and is released with it. iOS builds are numbered `X.Y.Z`, because the App Store accepts no prerelease suffix; Android builds get a version code that grows with every release, prereleases included.
- The phone app's native projects are generated from `apps/mobile/app.config.ts` with the SDK 56 template pinned (`npm run mobile:prebuild`); `expo` 56.0.16 bundles the next SDK's template. Android release builds must be signed with a key from the environment and fail without one, instead of falling back to the template's debug key.
- The iOS app's network policy names what it needs, local networking and Tailscale `ts.net` host names, instead of allowing arbitrary plain-HTTP loads, a setting iOS ignores when local networking is also allowed. Its permission prompts are in English.
- A local `npm run build:mac` builds only for the architecture of the Mac it runs on, like the CI jobs. It used to also emit the other architecture's file names from the same app.
- The phone app's interface is in English throughout; it mixed in German labels and German date formats. Dates and file sizes follow the device's locale.
- The desktop's permission presets, Bypass warning, chat modes and message queue come from `@betterc0de/schema`, which the phone app uses too; the desktop behaves as before.
- So do the desktop's "Always allow" rules, its tool steps built from activities, its provider-handoff presentation and its provider names; again the desktop behaves as before. The "Always allow" rules gained tests of their own: which commands and paths may be remembered, and that a provider's unscoped suggestion is never stored.
- The desktop's system instruction, the helpers that gather its skills, MCP servers and subagents, and its hooks' environment come from `@betterc0de/schema`, where the desktop's backend uses them for messages from the phone; the desktop behaves as before.
- The desktop's diff parser and what a generated commit message is based on come from `@betterc0de/schema` (`git-diff`, `git-commit-message`), which the phone app's source control uses too; the desktop behaves as before.
- The Android app asks only for the camera (to scan the pairing QR code, and to take a photo for a message), network access and vibration. The storage, "display over other apps" and biometric permissions that the React Native template and a library declared are removed; the app uses none of them.
